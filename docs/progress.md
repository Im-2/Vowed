Design decisions that differ from or extend the SPEC (flagged for review):
1. **`sweep_treasury` added.** The SPEC says dust goes to the treasury but has no instruction to move it. This permissionless instruction sends the vault's leftover (fee, unclaimable forfeits, dust) to the treasury only after every non-zero claim is done.
2. **Pool status:** stored as Open / Settling / Settled / Voided. "Active" is derived from the clock, not stored.
3. **Hard-mode losers have nothing to claim**, so they are not counted in `pending_claims` and cannot block the sweep.
4. **`void_pool` only before any payout** (Open or Settling, nothing claimed); it refunds full stakes to everyone, including participants already marked Failed.
5. **`settle_grace_secs` in Config (max 2 days)**: settlement opens end_ts + grace; check-ins close at the same moment, so they never overlap. Check-in window per day = the local day plus 2h grace.
6. **`init_config` only by the program upgrade authority** (prevents front-running of a fresh deployment).
7. **Token-2022 mints with extensions are rejected** by size check. No integration test for this yet (listed in the threat model).
8. Pool PDA seeds include creator and a creator-chosen id; fee is snapshotted per pool.
